## 2026-10-26 - [Python Dataclass Runtime Vulnerability]
**Learning:** Python dataclasses do not inherently validate types at runtime. Passing `None`, `{}`, or missing keys via `__init__` correctly raises `TypeError`. However, passing unexpected scalar strings (like "UNKNOWN") to fields annotated as `Enum` bypasses the type checker at runtime and allows the object to instantiate with corrupted state. Without manual validation in `__post_init__`, fail-closed validation methods like `is_safe_deployable()` can subsequently evaluate to `True` on this corrupted data (a bypass that was addressed in PR #196).
**Action:** Always validate enum instantiations and structure types if the payload originates from untrusted sources. This must be done manually by implementing a `__post_init__` check, using a `from_dict` parsing method, or utilizing a runtime validation library like `pydantic`. These validations are crucial for asserting strict security boundaries in fail-closed gates.
