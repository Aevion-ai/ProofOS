## 2024-10-10 - Missing Path Traversal Validations in MIRROR_MANIFEST.md Parsing
**Vulnerability:** The `.github/workflows/mirror-from-monorepo.yml` workflow parses paths from `MIRROR_MANIFEST.md` and passes them directly to file system operations (like `shutil.rmtree`, `shutil.copytree`, `shutil.copy2`, `dst_path.parent.mkdir`) without path sanitization or bounded validation. This could allow a malicious PR modifying the untrusted `MIRROR_MANIFEST.md` to trigger arbitrary file read/write (e.g. overwriting workflow files or other repositories files, traversing paths) inside the CI environment.
**Learning:** Even internal configuration files used in CI workflows (like `MIRROR_MANIFEST.md`) must be treated as untrusted data sources when they control file system operations. The values parsed must be bounded and validated against intended base directories using `is_relative_to` to prevent arbitrary file access or CI exploits.
**Prevention:** Apply path sanitization and boundary validation (e.g., using `Path.resolve()` and `Path.is_relative_to()`) for any paths derived from externally provided or repository-hosted manifest files, and explicitly deny control-plane modification overrides.
