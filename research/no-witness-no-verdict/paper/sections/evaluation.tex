The reference implementation is a Python package
(\texttt{nowitnessnoverdict}) with three modules: the fail-closed gate
(\texttt{fail\_closed.py}), candidate-only reflection
(\texttt{candidate\_only.py}), and receipt-bound replay and resume
(\texttt{receipt.py}). Formal statements are provided as Lean 4 theorems
(\texttt{lean/NoWitnessNoVerdict/*.lean}) mirroring the six claims.

\subsection{Admission disposition vs.\ execution outcome}

The final distinction matters: \texttt{admission\_disposition} records
whether the transition was authorized; \texttt{execution\_outcome} records
whether the authorized command actually succeeded. An authorized command
may fail with exit code 1; the receipt must record
\texttt{ADMIT} + \texttt{execution\_outcome=FAILURE} and must not turn
authorization into a claim that execution succeeded.

\subsection{Resume semantics}

Following the machine-checked resume-contract literature
\cite{resume_contract}, receipts classify each transition as NEW, RETRIED,
RESUMED, FORKED, REPLAYED, or COMPENSATED, and carry checkpoint identity,
state digests, execution-prefix digests, prior-effect-set digests, resume
nonces, consume claims, fork intent, recovery epoch, attempt number, and
effect idempotency keys. The resume gate enforces consume-once and
checkpoint validity before a resumed transition may proceed.
